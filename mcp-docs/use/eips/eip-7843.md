# EIP-7843 — SLOTNUM opcode

> **Status:** **Planned** — header slot on `run_bytecode` / `run_block` not yet shipped; **public MCP not launched yet**. Use the [website exploration](https://feelyourprotocol.org/eip-7843-slotnum-opcode) today.

## What became possible

**How do you read the beacon slot on-chain without hardcoding 12-second slots?** EIP-7843 adds **`SLOTNUM`** (`0x4b`): the consensus layer writes the slot on the execution header, and the opcode pushes it for 2 gas.

Dividing the block timestamp by 12 works only while slots stay 12 seconds. The opcode abstracts that away.

When **`run_block`** (and a `slotNumber` field on simulate) ships, the MCP server will run **your** bytecode under a chosen slot and return the stack top — Osaka (invalid opcode) vs Amsterdam (header slot).
