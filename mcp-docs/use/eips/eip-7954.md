# EIP-7954 — Contract size limits

> **Status:** **Planned module.** Use the [website exploration](https://feelyourprotocol.org/eip-7954-contract-size-limit) today.

## What became possible

**How much contract code can you deploy before the protocol rejects it?** EIP-7954 raises the deployed runtime-code limit from **24 KiB to 64 KiB** and the separate initcode limit from **48 KiB to 128 KiB**. Existing contracts do not change. New deployments get more room, but both boundaries remain consensus validity checks.

The intended MCP twin will run the same caller-supplied contract-creation transaction on **Fusaka** and **Glamsterdam**, then report whether deployment succeeded and how much runtime code was installed.

## What you can ask your agent

Once contract creation is available through `run_transaction`, try prompts like:

- _“Would this 24,577-byte contract deploy on Fusaka and Glamsterdam?”_
- _“Deploy this initcode at the exact EIP-7954 runtime-code ceiling.”_
- _“Run the same deployment one byte above the new limit — how does it fail?”_
- _“Is my deployment blocked by initcode size or deployed runtime-code size?”_

These are inspiration prompts. The caller supplies the initcode; the MCP catalogue does not ship demo contracts.

## Planned server path

1. [Discover support](/use/tools/describe-capabilities) — wait for an EIP-7954 runnable catalogue entry.
2. [Run transaction](/use/tools/run-transaction) — submit a contract-creation transaction on `fusaka`.
3. Repeat on `glamsterdam` and compare deployment success, error, created address, and deployed code size.

Today `run_transaction` requires a recipient and therefore runs message-call transactions only. The EIP-7954 module remains Planned until the generic verb supports contract creation and exposes enough result data to show the changed boundary honestly.

## Fork caveat

Glamsterdam is the combined-upgrade name; `amsterdam` is its execution-layer alias. The current spec limits are **65,536 bytes** of runtime code and **131,072 bytes** of initcode. Earlier discussion used smaller values, so use the current EIP rather than the historical thread title.
