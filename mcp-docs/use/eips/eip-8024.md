# EIP-8024 — DUPN, SWAPN, EXCHANGE

> **Status:** **Runnable** on Amsterdam via MCP stdio v0.1.

## What became possible

On **Amsterdam**, the EVM executes three new stack opcodes: **DUPN** (`0xe6`), **SWAPN** (`0xe7`), and **EXCHANGE** (`0xe8`). They extend deep stack access beyond `DUP16` / `SWAP16` without breaking backward compatibility.

The MCP server runs **any** raw bytecode you (or your agent) supply under Amsterdam and returns deterministic gas, stack, and optional traces. It does not ship fixed demo programs — your agent constructs bytecode from the spec.

## What you can ask your agent

Connect the MCP server ([Connect](/use/connect)), then try prompts like:

- *“Is EIP-8024 supported on Amsterdam? Call describe_capabilities and summarize.”*
- *“Give me a minimal DUPN example for depth 17, encode it as bytecode, and run it on Amsterdam with trace.”*
- *“I have this pre-Amsterdam stack-manipulation bytecode — rewrite it using SWAPN where it helps, then compare gas before and after.”*
- *“Run this bytecode on Amsterdam and tell me if DUPN succeeds or fails and why.”*
- *“Compare two variants: my original bytecode vs a DUPN-based rewrite on Amsterdam.”*

These are **inspiration prompts** — the agent builds bytecode and calls the generic tools below.

## Which MCP tools

| Step | Tool | Purpose |
| --- | --- | --- |
| 1 | [`describe_capabilities`](/use/tools/describe-capabilities) | Confirm 8024 is runnable; read opcode encoding from the live catalog |
| 2 | [`simulate_evm_bytecode`](/use/tools/simulate-bytecode) | Run one bytecode program |
| 3 | [`compare_evm_variants`](/use/tools/compare-variants) | Diff gas/success across labelled variants |

## Fork caveat

**Amsterdam already bundles EIP-8024** in EthereumJS v10. Passing `eips: [8024]` is accepted but is **not** a before/after toggle. This server does not yet offer a pre-8024 base hardfork, so you cannot simulate “8024 off” on Amsterdam.
