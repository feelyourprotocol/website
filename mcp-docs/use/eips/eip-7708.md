# EIP-7708 — ETH transfers emit a log

> **Status:** **Planned** — simulate tool does not yet return receipt logs; **public MCP not launched yet**. Use the [website exploration](https://feelyourprotocol.org/eip-7708-eth-transfer-logs) today.

## What became possible

**When does native ETH show up as a Transfer log — and when does it stay invisible to log filters?** EIP-7708 emits synthetic ERC-20-compatible `Transfer` logs from the system address for nonzero ETH moves (tx value, `CALL`, `CREATE`/`CREATE2`, `SELFDESTRUCT`).

When the **simulate** shape exposes receipt logs, the MCP server will let agents compare Amsterdam vs Osaka on the same bytecode or transaction — the headless twin of the website scenarios (plain transfer → contract wallet → zero-value → reverted CALL).

## What you will ask your agent (when simulate returns logs)

[Connect](/use/connect) now so you are ready; try these once log output ships:

- *“Run a plain 1 wei transfer on Amsterdam — decode the EIP-7708 Transfer log in the receipt.”*
- *“Same transaction on Osaka vs Amsterdam — which receipt logs differ?”*
- *“My contract wallet forwards ETH via CALL — show me the Transfer log fields (from, to, value).”*
- *“Why is there no Transfer log when the inner CALL reverts?”*

Until simulate returns logs, use the [website exploration](https://feelyourprotocol.org/eip-7708-eth-transfer-logs) for the interactive receipt panel.
