## What became possible

<LeadQuestion text="When does native ETH show up as a Transfer log — and when does it stay invisible to log filters?" />

EIP-7708 emits synthetic ERC-20-compatible `Transfer` logs from the system address for nonzero ETH moves (tx value, `CALL`, `CREATE`/`CREATE2`, `SELFDESTRUCT`).

The MCP server runs a **value-bearing transaction** (`run_transaction`) and returns **`logs`** plus **`decodedLogs`** (EIP-7708 Transfer/Burn decorations when present). Compare **Fusaka** vs **Glamsterdam** on the same tx — preview emits Transfer logs; baseline stays silent.

```json
{
  "from": "0x00000000000000000000000000000000000000ee",
  "to": "0x00000000000000000000000000000000000000aa",
  "value": "1",
  "fork": { "baseHardfork": "glamsterdam" }
}
```

Optional **`code`** installs runtime bytecode at `to` before the tx (contract-wallet style scenarios). Inner CALL programs may also use [Run bytecode](/use/tools/run-bytecode).

::: warning Fork caveat
Run the **same transaction twice** — **`fusaka`** (baseline), then **`glamsterdam`** (preview) — and compare **`decodedLogs`**. EIP-7708 Transfer decorations appear only on Glamsterdam for successful nonzero value moves. Do not infer Transfer events from opcode traces alone.
:::
