## What became possible

<LeadQuestion text="Why isn't 21,000 gas enough for a simple ETH transfer anymore?" />

EIP-8037 splits gas into an execution dimension and a state dimension. Creating a new account (first-touch value transfer) charges state-creation gas — about 183,600 (`120 × 1530`) — on top of familiar execution gas. A first write to an empty storage slot charges about 97,920 (`64 × 1530`).

The MCP server runs a **value-bearing transaction** (`run_transaction`) and returns **paid `gasUsed`** (`gasUsedScope: transaction`). On Glamsterdam it also returns **`txRegularGas`** / **`txStateGas`**. Compare **Fusaka** vs **Glamsterdam** — preview includes state gas; baseline does not. A first-touch transfer is about **21,000 vs 204,600**.

```json
{
  "from": "0x00000000000000000000000000000000000000ee",
  "to": "0x00000000000000000000000000000000000000aa",
  "value": "1",
  "fork": { "baseHardfork": "glamsterdam" }
}
```

`to` should be an empty / never-funded account so Glamsterdam includes first-touch state gas. Repeat with `"baseHardfork": "fusaka"`. Prefund `to` via `accounts` to collapse account-creation gas. Optional `gasLimit: "21000"` shows Glamsterdam failing.

SSTORE programs may also use [Run bytecode](/use/tools/run-bytecode).

::: warning Fork caveat
Run the **same transaction twice** — **`fusaka`** (baseline), then **`glamsterdam`** (preview). Lead with **`gasUsed`** (paid tx gas): about **21,000 vs 204,600** for first-touch. On Glamsterdam, `txStateGas` is the state dimension (~183,600).
:::
