# EIP-8037 — State creation gas

> **Status:** **Runnable via simulate** (`gasUsed` on Amsterdam vs Osaka). A named EIP-8037 catalog row ships with the engine follow-up. Public MCP not launched. Use the [website exploration](https://feelyourprotocol.org/eip-8037-state-creation-gas) today.

## What became possible

**Why isn't 21,000 gas enough for a simple ETH transfer anymore?** EIP-8037 splits gas into an execution dimension and a state dimension. Creating a new account (first-touch value transfer) charges state-creation gas — about 183,600 (`120 × 1530`) — on top of the familiar 21,000 execution gas.

Today's **simulate** verb already shows the effect: the same 1-wei `messageCall` to an empty account reports `gasUsed: "0"` on Osaka and `gasUsed: "183600"` on Amsterdam (call-frame state gas, not a full 21,000-gas tx). Compare **Osaka** vs **Amsterdam** and read **`gasUsed`**. The website widget uses a full `runTx` so the 21,000 vs recommended `gasLimit` failure is visible; MCP `messageCall` does not apply tx intrinsic 21,000.

## What you can ask your agent

Once the public MCP is live ([Connect](/use/connect)), try prompts like:

- *“Run a 1 wei messageCall to an empty account on Amsterdam — what is gasUsed?”*
- *“Same call on Osaka vs Amsterdam — how does gasUsed differ?”*
- *“Why would a wallet that still uses gasLimit 21000 fail a first-touch transfer after Amsterdam?”*
- *“If the recipient already has a balance, does Amsterdam still add state-creation gas?”*

These are **inspiration prompts** — curiosity, understanding, or builder checks.

## What the server does

| Step | Action | Purpose |
| --- | --- | --- |
| 1 | [Discover support](/use/tools/describe-capabilities) | Confirm simulate on Amsterdam / Osaka (named 8037 row follows in the engine module) |
| 2 | [Run bytecode](/use/tools/run-bytecode) | Execute a value `messageCall` on **`amsterdam`** or **`osaka`**; read `gasUsed` |

Use **`messageCall`** for a plain ETH move without wrapper bytecode:

```json
{
  "messageCall": {
    "caller": "0x00000000000000000000000000000000000000ee",
    "to": "0x00000000000000000000000000000000000000aa",
    "value": "1"
  },
  "fork": { "baseHardfork": "amsterdam" }
}
```

`to` should be an empty / never-funded account so Amsterdam includes first-touch state gas. Repeat with `"baseHardfork": "osaka"` and diff `gasUsed`.

## Fork caveat

Run the **same program twice** — **`osaka`** (baseline), then **`amsterdam`** (preview) — and compare **`gasUsed`**. Do not treat that number as a full transaction `gasLimit`: MCP messageCall is a call frame, so Osaka often reports `0` for a plain value move. The 21,000 intrinsic only appears on a real tx (the website exploration).

**Limits today:** no two-dimensional `txRegularGas` / `txStateGas` fields on the simulate result; no wallet `gasLimit` 21000 path. Those land with a named 8037 catalog entry.
