# EIP-7778 — Block gas accounting without refunds

> **At public launch:** runnable on Amsterdam on the hosted MCP (free; opens launch week 5–9 Oct 2026). Website twin: [exploration](https://feelyourprotocol.org/eip-7778-block-gas-accounting).

## What became possible

**I cleared storage and got a refund — why does the block still count the full gas?** EIP-7778 keeps the refund on the sender's bill. The block still counts the gas from before that refund. A storage clear that creates no new state shows two numbers on Glamsterdam (you pay less than the block counts) and one number on Fusaka.

Warm access and putting a slot back to its original value still reduce what the block counts. Those are cheaper work, not a refund subtracted after the fact.

## What you can ask your agent

Once the public MCP is live ([Connect](/use/connect)), try prompts like:

- _“Clear a nonzero storage slot on Glamsterdam. What do I pay, and what does the block count?”_
- _“Same clear on Fusaka — do the two numbers match?”_
- _“Rewrite a nonzero slot to another nonzero value. Does the bill still match the block?”_
- _“If I write a new value and then put the original back, does the block still get the discount?”_
- _“Can a block of storage-clearing transactions sneak past the gas limit because of refunds?”_

These are **inspiration prompts** — curiosity, understanding, or builder checks.

```json
{
  "from": "0x0000000000000000000000000000000000000077",
  "to": "0x0000000000000000000000000000000000000078",
  "code": "0x600060045500",
  "accounts": [
    {
      "address": "0x0000000000000000000000000000000000000078",
      "storage": [{ "slot": "0x04", "value": "0x09" }]
    }
  ],
  "fork": { "baseHardfork": "glamsterdam" }
}
```

`code` writes 0 into slot 4. The slot must already be nonzero, and the transaction must not create new state — if state gas is the larger dimension, `header.gasUsed` hides the refund gap. On Glamsterdam, `gasUsed` (what you pay) is below `txRegularGas` (what the block counts). On Fusaka, `txRegularGas` is absent and `gasUsed` is both numbers.

A lab block with the same transaction reports the gap as `header.gasUsed` versus `transactions[].gasUsed`.

## Fork caveat

Run the **same transaction twice** — **`fusaka`** (baseline), then **`glamsterdam`** (preview). Lead with paid `gasUsed` against the block count (`txRegularGas` or `header.gasUsed`). Receipt gas follows what the sender pays in this lab. The block count is the separate figure.
