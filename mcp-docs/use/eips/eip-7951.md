# EIP-7951 — secp256r1 Precompile

> **Status:** **Ready for the public MCP** (not launched). Use the [website exploration](https://feelyourprotocol.org/eip-7951-secp256r1-precompile) today.

## What became possible

**Why add a secp256r1 precompile?** EIP-7951 exposes P-256 (the curve behind Apple/Android passkeys and WebAuthn) at address **`0x100`**. Contracts can verify device-native signatures on-chain. The precompile is **live on Fusaka** (current mainnet EL).

The MCP server runs **caller-supplied bytecode** that `CALL`s the precompile with five 32-byte fields: message hash, `r`, `s`, public key `x`, public key `y`. A valid signature returns **`0x01`** (32 bytes). Invalid payloads fail or return empty data — your agent can explore both. There is no dedicated precompile input tool; construct a `CALL` to `0x100`.

## What you can ask your agent

Once the public MCP is live ([Connect](/use/connect)), try prompts like:

- *“Verify this P-256 / WebAuthn payload on current mainnet EL (Fusaka) — does 0x100 return 0x01?”*
- *“I'm adding passkey verification to a wallet — run my test vector on Fusaka and explain a valid vs invalid return.”*
- *“Help me encode hash, r, s, pubX, pubY for the 0x100 precompile, then run the CALL.”*
- *“What gas does this secp256r1 verification cost on Fusaka?”*

These are **inspiration prompts** — curiosity, understanding, or builder checks. Fusaka is the run target; you do not need a preview fork for 7951.

## Fork caveat

Available on **Fusaka** (mainnet) and later lineage forks. Teaching is **valid vs invalid** return data, not a gas delta vs Pectra. The probe may list a Pectra→Fusaka pair (activation); that is “precompile missing vs present,” not a pricing lesson.
