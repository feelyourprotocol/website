# EIP-7883 — ModExp Gas Cost Increase

> **Status:** **Ready for the public MCP** (not launched). Use the [website exploration](https://feelyourprotocol.org/eip-7883-modexp-gas-cost-increase) today.

## What became possible

**How are ModExp gas costs changing with Fusaka?** EIP-7883 recalibrates the ModExp precompile (`0x05`) gas formula so cost better reflects real work — especially for larger exponents. EIP-7823 (same fork) tightens input bounds. The new formula is **live on Fusaka** (current mainnet EL).

The MCP server runs **caller-supplied bytecode** that invokes ModExp (typically a `CALL` to `0x05` with the standard ABI: three 32-byte length headers plus `B`, `E`, `M` bodies). Run on **Fusaka** to price today’s mainnet; compare **Pectra** vs **Fusaka** to see the repricing — or sweep input sizes on Fusaka alone to understand the curve.

## What you can ask your agent

Once the public MCP is live ([Connect](/use/connect)), try prompts like:

- *“How much gas does ModExp use for this 32-byte RSA-style exponent on current mainnet EL (Fusaka)?”*
- *“Compare the same B/E/M payload on Pectra vs Fusaka — what did the gas jump?”*
- *“Run ModExp with these B/E/M hex fields on Fusaka and tell me if EIP-7823 rejects the input.”*
- *“Compare ModExp gas for my airdrop verification input on pre-Fusaka and post-Fusaka rules.”*

These are **inspiration prompts** — play, understand, or check *your* inputs.

| Step | Action | Purpose |

| 2 | [Run bytecode](/use/tools/run-bytecode) | Execute CALL bytecode on `fusaka` (or `pectra` then `fusaka` for compare) |

## Fork caveat

EIP-7883 **introduced at Fusaka** (current mainnet). For **before/after**, run the same bytecode on **`pectra`** (predecessor), then **`fusaka`**, and diff `gasUsed`. The probe derives this pair from `eipIntroductions`. A Fusaka-only run is enough when you only need today’s ModExp cost.
