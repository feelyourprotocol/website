# EIP-7928 — Block Level Access Lists

> **Status:** **Runnable** on MCP — **`generate`** (lab BAL JSON + hash) and **`inspect`** (structure/hash without chain state). BYOS lab only; not mainnet block replay.

## What became possible

**What does the block commit to besides state root?** EIP-7928 adds a **block-level access list (BAL)**: every balance, nonce, code, and storage touch during block execution, hashed as **`blockAccessListHash`** in the header.

Use **`generate`** with the same inputs as [Run block](/use/tools/run-block) (1–8 impersonated txs, optional accounts, optional header) on **Amsterdam** to derive BAL JSON and `hash`. Use **`inspect`** on a BAL you already have for encoding, canonical order, item cap, and optional hash match — layers A–C, not consensus replay against archive mainnet state.

## What to ask your agent

- *“Generate a BAL for a block with one plain ETH transfer — what does the access list contain?”*
- *“Run the EIP-7928 curriculum step: SSTORE write — show me the BAL JSON and hash.”*
- *“Inspect this BAL JSON — is it well formed and does the hash match `0x…`?”*
- *“Two transfers in one lab block — show blockAccessIndex on each change.”*

The [website exploration](https://feelyourprotocol.org/eip-7928-block-level-access-lists) remains the interactive textbook; MCP is the headless twin.

## What the server does

| Step | Action | Purpose |
| --- | --- | --- |
| 1 | [Discover support](/use/tools/describe-capabilities) | Confirm EIP-7928 module, `inspectKinds`, Amsterdam |
| 2 | **`generate`** | Derive BAL from your lab block |
| 3 | **`inspect`** (optional) | Validate caller-supplied BAL JSON or RLP hex |

**Limits:** Amsterdam only for generate; 1–8 txs; empty-ish world unless you prefund accounts; no claim that a BAL came from mainnet block *N* without parent state.
