# x402 & the Agent Economy

> High-level outline of how payments and discovery work in the agent economy we're building for. Pricing specifics live in [Pricing & Cost Model](/monetization/pricing).

## Why this matters

When the primary API consumer is an **autonomous AI agent**, not a human, the whole commercial model changes. Agents don't sign up, manage API keys, or type in card numbers — but they *do* carry wallets and can pay programmatically. The rails for that have just matured.

## x402 — payment

[x402](https://x402.org) revives the dormant **HTTP 402 "Payment Required"** status code as a standard for machine-to-machine payments.

The flow, in short:

1. Agent requests a simulation.
2. Server replies **`402 Payment Required`** with a price (e.g. USDC on Base), quoted **dynamically** based on the request.
3. Agent signs a gasless stablecoin transfer authorization and retries with the signature in the header.
4. A **facilitator** verifies and settles the payment on-chain; the server then runs the simulation and returns the result.

Why it fits: it's permissionless, account-less, and built exactly for agents paying for API access. We can lean on existing middleware and facilitators (e.g. Coinbase/Stripe) rather than building settlement ourselves.

## MCP — integration

A bare REST API isn't enough: an LLM can't reliably guess how to call complex endpoints. We ship an **MCP server** (see [The Agent API & MCP Server](/concepts/api-mcp)) so agents get explicit, self-describing tools — the "agent bindings" that make the API usable out of the box.

## Discovery — registries

Agents find tools through **MCP registries** (e.g. the official `registry.modelcontextprotocol.io`, plus gateways/marketplaces), and enterprises mirror tools into private registries. Discovery is real but not magic: it rewards precise metadata and good docs, and humans still allowlist tools for high-stakes tasks — so registry presence pairs with active [distribution](/gtm/distribution).

## Timing — why now

We're in a "Goldilocks window" in mid-2026: the standards have hardened (MCP for *how agents talk*, x402 for *how agents pay*, ERC-8004 for *agent identity*), facilitators are in production, but the high-value, domain-specific endpoints — like a deterministic EVM oracle — mostly **don't exist yet**. Build a year ago and you'd be writing the plumbing; wait a year and the registries fill up.

## A note on identity & anti-abuse

ERC-8004 (trustless agent identities) and simple on-chain checks (e.g. a minimum wallet balance) give cheap, effective spam resistance without human-style signups — relevant to how we keep the service open yet protected (see [Pricing & Cost Model](/monetization/pricing#anti-abuse)).
