# x402 & the Agent Economy (Concept)

> **Payment rails in progress.** The MCP **oracle is built**; x402 wires how agents pay for the hosted endpoint at [launch week](/roadmap/launch). Pricing specifics: [Pricing & Cost Model](/monetization/pricing).

## Why this matters

When the primary API consumer is an **autonomous AI agent**, not a human, the commercial model changes. Agents don't sign up, manage API keys, or type in card numbers — but they *can* carry wallets and pay programmatically. The rails for that have matured recently, which is why we're integrating them for the public launch — not inventing bespoke billing.

**Important framing:** x402 is how agents **access** the deterministic oracle — not the product itself. The hook is ground truth for upcoming fork rules; payment is the permissionless on-ramp.

## x402 — payment _(planned for launch week)_

[x402](https://x402.org) revives the dormant **HTTP 402 "Payment Required"** status code as a standard for machine-to-machine payments.

The flow we're designing toward:

1. Agent requests a simulation on the hosted MCP.
2. Server replies **`402 Payment Required`** with a price (e.g. USDC on Base), quoted **dynamically** based on the request.
3. Agent signs a gasless stablecoin transfer authorization and retries with the signature in the header.
4. A **facilitator** verifies and settles the payment on-chain; the server then runs the simulation and returns the result.

Why it fits: permissionless, account-less, and built for agents paying for API access. We'd lean on existing middleware and facilitators (e.g. Coinbase/Stripe) rather than building settlement ourselves — integration is the current engineering focus.

## MCP — delivery _(shipped as tools; hosted HTTP pending)_

Agents need explicit, self-describing tools — not guessed REST endpoints. We deliver through an **MCP server** (see [Agent API & MCP (Concept)](/concepts/api-mcp)): `describe_capabilities` and `run_evm_bytecode` are implemented; the public HTTP transport ships at launch.

## Discovery — registries _(post-launch GTM)_

Agents find tools through **MCP registries** (e.g. the official `registry.modelcontextprotocol.io`, plus gateways/marketplaces). Discovery rewards precise metadata and good docs; humans still allowlist tools for high-stakes tasks — so registry presence pairs with active [distribution](/go-to-market/distribution) once the hosted endpoint is live.

## Timing — why now

We're in a "Goldilocks window" in 2026: the standards have hardened (MCP for *how agents talk*, x402 for *how agents pay*), facilitators are in production, and domain-specific deterministic endpoints — like an EVM oracle for upcoming forks — are still sparse. The engineering core landed in summer 2026; **launch week** is when we put payment + hosted access together in public.

## A note on identity & anti-abuse

ERC-8004 (trustless agent identities) and simple on-chain checks (e.g. a minimum wallet balance) could give cheap, effective spam resistance without human-style signups — relevant to how we'd keep the service open yet protected (see [Pricing & Cost Model](/monetization/pricing#anti-abuse)). Directional only; not implemented.
